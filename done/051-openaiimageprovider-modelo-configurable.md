# 051 — OpenAiImageProvider: modelo configurable

**Milestone:** M9 · **Depende de:** 025 · **HUs:** HU-39, HU-40 · **Épica:** M (`docs/definiciones/galgoth-studio-fase3-textura.md`)

## Objetivo
Nace de `docs/definiciones/galgoth-studio-fase3-textura.md` (Diseño técnico §5/§12, valor default corregido en la ronda de VoBo final del 10 sep 2026). Implementación real de `ImageGenerationProvider` (interfaz ya definida en 025, hasta ahora sin proveedor real) vía OpenAI, con el modelo de imagen **configurable** (nunca hardcodeado en dominio/lógica de negocio). `MockImageProvider` pasa de placeholder de interfaz a un doble determinista real y utilizable en tests.

## Criterios de aceptación (TDD)
- Dado `ImageGenerationProvider.generateTextureSheet(TextureGenerationSheetRequest)` (extensión aditiva sobre la interfaz de 025), cuando se agrega, entonces `generateImage(String)` permanece sin cambios — los tests existentes de 025 siguen en verde sin modificarlos.
- Dado `ai.openai.image-model=${OPENAI_IMAGE_MODEL:gpt-image-2.5-sunburst-2026-09-08}` (snapshot fechado, preferido sobre un alias flotante por reproducibilidad), cuando `OpenAiImageProvider` arma una llamada, entonces usa el valor configurado — nunca un literal de modelo en el cuerpo de la petición ni en ninguna clase de dominio.
- Dado que existe una región/contenido a preservar (inpaint), cuando se genera, entonces se usa `/v1/images/edits` con máscara/imagen base; sin contenido previo, entonces se usa `/v1/images/generations` — verificar contra la documentación real de OpenAI vigente al implementar (ambos endpoints/capacidades pueden requerir ajuste).
- Dado que se dispara cualquier llamada de generación, cuando se registra el job (`ai_jobs`), entonces `ai_jobs.model` persiste EXACTAMENTE el valor configurado en `ai.openai.image-model` en ESE momento — test que cambia la configuración entre dos llamadas y confirma que cada `ai_jobs` guardó el valor real usado en su momento, no el más reciente.
- Dado `MockImageProvider`, cuando se usa en tests, entonces es un doble determinista real (produce bytes de imagen reproducibles/verificables), no solo una interfaz sin comportamiento — mismo patrón que `MockProvider`/`MockReasoningProvider` de 025.

## Hecho

Implementado en la rama `feature/051-openaiimageprovider-modelo-configurable`.

- `ImageGenerationProvider.generateTextureSheet(TextureGenerationSheetRequest)` agregado de forma ADITIVA (Diseño técnico §11). Forma EXACTA usada (idéntica a la del ticket/diseño técnico, anidada dentro de la interfaz):
  ```java
  record TextureGenerationSheetRequest(String prompt, byte[] referenceImageBytes, int sheetWidth, int sheetHeight, String style) {}
  ```
  `generateImage(String)` no cambió de forma ni de contrato; `MockImageProviderTest` original sigue en verde sin modificar su test existente.
- Nuevo `OpenAiImageProvider` (`aiorchestrator/provider/`): mismo patrón HTTP que `ClaudeMessagesClient` (`RestClient`, sin dependencia nueva). Sin `referenceImageBytes` (o vacío) -> `POST /v1/images/generations` (JSON: `model`/`prompt`/`size`/`n`/`response_format=b64_json`); con `referenceImageBytes` -> `POST /v1/images/edits` (multipart: `model`/`prompt`/`size`/`image`). Ambos decodifican `data[0].b64_json`. `style` se pliega como instrucción de texto al final del prompt (no existe un parámetro `style` genérico en `/v1/images/*` fuera de DALL-E-3 `vivid`/`natural`, que no aplica a un snapshot `gpt-image-*` -- decisión documentada en el Javadoc de `ImageGenerationProvider.TextureGenerationSheetRequest`, a confirmar/ajustar cuando 054 conecte el pipeline completo contra la API real). `OpenAiImageProvider#model()` expone el modelo configurado para que 054 lo persista en `ai_jobs.model` cuando exista el orquestador.
- `application.properties`: `ai.image-provider=openai` (default) + `ai.openai.api-key=${OPENAI_API_KEY:}` + `ai.openai.image-model=${OPENAI_IMAGE_MODEL:gpt-image-2.5-sunburst-2026-09-08}` + `ai.openai.base-url=https://api.openai.com` -- mismo estilo que las properties de Claude ya existentes. `docker/.env.example` actualizado con `OPENAI_API_KEY`/`OPENAI_IMAGE_MODEL`.
- `AiProviderConfig`: nuevos beans `openAiImageProvider`/`mockImageProvider` para `ImageGenerationProvider`, seleccionados por `AI_IMAGE_PROVIDER` (relaxed binding -> `ai.image-provider`), mismo mecanismo `@ConditionalOnProperty` que vision/reasoning (default `openai`).
- `MockImageProvider` deja de ser un placeholder de interfaz: `generateTextureSheet` sin configurar genera un PNG sintético determinista (tablero de ajedrez vía `ImageIO`) con las dimensiones EXACTAS pedidas, decodificable/verificable en tests; `setNextTextureSheet(bytes)` lo hace configurable (mismo patrón que `MockReasoningProvider#setNextResponse`). `generateImage(String)` sin cambios de comportamiento.
- **Explícitamente NO tocado (fuera de alcance, sin parches silenciosos)**: `TextureGenerationSheetPlanner`/`TextureSheetSlicer`/`TextureCompositorService` (ticket 053) y el pipeline orquestador completo que registraría/actualizaría `ai_jobs` (ticket 054) -- ninguno de los tres existe todavía, así que el AC del ticket sobre "cada `ai_jobs` guarda el modelo real usado en su momento" no se pudo verificar contra una fila de `ai_jobs` real; se verificó a nivel de proveedor (dos instancias con `ai.openai.image-model` distinto configurado en el constructor reportan y envían cada una su propio valor, sin estado estático compartido entre ellas) -- 054 tiene `OpenAiImageProvider#model()` disponible para leer el valor real en el momento de cada llamada y persistirlo.
- Gap señalado para DevOps/054: `deploy/docker-compose.{dev,qa,prod}.yml` no pasan `OPENAI_API_KEY`/`OPENAI_IMAGE_MODEL` al contenedor (solo `ANTHROPIC_API_KEY` hoy) -- no rompe nada mientras nada invoque `generateTextureSheet` en producción (054 aún no existe), pero hay que cablearlo cuando 054 aterrice.
- Tests: `OpenAiImageProviderTest` (8, `MockRestServiceServer`, sin red real -- generations, edits/multipart, selección de endpoint, modelo por-instancia sin estado compartido, error HTTP, respuesta sin `b64_json`, sin API key), `MockImageProviderTest` (+4: PNG sintético con dimensiones exactas, determinismo, distingue por prompt/estilo, `setNextTextureSheet`), `AiProviderConfigTest` (+2: default OpenAI, `AI_IMAGE_PROVIDER=mock`). Backend completo: **330 tests, 0 failures, 0 errors** (`./gradlew test`).
