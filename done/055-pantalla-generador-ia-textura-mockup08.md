## Hecho

Implementado en `feature/055-pantalla-generador-ia-textura-mockup-08`, ensamblando el pipeline 100% backend de 054 en una pantalla frontend nueva -- sin tocar backend.

**Ruta nueva** `/projects/:projectId/mobs/:mobId/texture/generate-ai` -> `frontend/src/ai/texture/TextureAiGeneratorScreen.vue` (route-level, mismo patrón que `MobEditor.vue`/`ExportScreen.vue`, 034/032, y siguiendo el MISMO patrón de UI/UX ya probado por el wizard de generación de geometría -- `GenerationStep.vue`/`AiEditPanel.vue`, 029/031/038 -- en vez de inventar uno nuevo):

- **AC #1 (layout mockup 08)**: pantalla con imagen de referencia (reutiliza la MISMA ya subida en Fase 2, primer consumidor real de `GET /api/mobs/{mobId}/references`, 024), panel de resultado/preview (el ATLAS 2D, no el viewport 3D -- coherente con que 054 opera sobre píxeles), selector de Estilo con las 4 opciones (radios nativos: Fiel a la referencia/Minecraft Vanilla/Pixel Art/Realista), control de Detalle bajo-alto (`<input type=range>` de 3 posiciones -> low/medium/high) y selector "Parte a generar" (`<select>`: "Modelo completo" + un bone por cada bone CON geometría, mismo filtro que el backend usa para rechazar bones vacíos).
- **AC #2 (progreso SSE + preview incremental)**: reutiliza `GET /api/jobs/{jobId}/events` (`eventsUrl` de `generationApi.ts`) tal cual. Nuevo `frontend/src/ai/texture/textureGenerationStages.ts` (7 tests) normaliza el único stage dinámico del pipeline (`generando_bone_<id>`) a una categoría fija para la lista de 5 etapas (`analizando_paleta`/`mapeando_caras`/`generando_bone`/`componiendo_atlas`/`limpiando_pixeles`) -- sin `cancelado` (no existe endpoint de cancelación para jobs de textura). `preview_texture_patch` se decodifica con el nuevo `texturePatchDecode.ts` (4 tests, mismo criterio de aislamiento de `createImageBitmap`/canvas real que `pngImportDecode.ts`, 048, para quedar testeable sin DOM real) y se compone incrementalmente sobre un `<canvas>` del tamaño real del atlas (`TextureDocument.width/height` del draft), pixel-perfect (`image-rendering: pixelated`).
- **AC #3 (diff Antes/Después + Apply/Reject, Visual Contract)**: al completar, el canvas se reemplaza por las 2 imágenes completas de `GET /api/jobs/{jobId}/texture-result` (`beforeAtlasPngBase64`/`afterAtlasPngBase64`) con el mismo toggle Antes/Después de `AiEditPanel.vue`. Muestra la advertencia reforzada de HU-37 AC #2 cuando `hasHandPaintedOverwrite=true`. "Rechazar" nunca llama a ningún endpoint (HU-38: "Reject no modifica ni el draft ni ninguna revisión" -- no existe un endpoint de reject, ver `docs/API.md`). "Aplicar" llama `POST /apply-texture`; un 409 `STALE_TEXTURE_BASE` se traduce a un aviso explícito con "Regenerar contra el estado actual" (mismo patrón que `STALE_EDIT_BASE`/031); un Apply exitoso navega de vuelta al editor del mob. Paleta dark graphite/mint accent, componentes del design system ya existentes (`GButton`/`GSidebar`/`IconButton`) -- sin reinterpretar el Visual Contract.
- Nuevos clientes HTTP: `frontend/src/api/textureGenerationApi.ts` (`startTextureGeneration`/`getTextureResult`/`applyTexture`, 5 tests) y `listReferenceImages`/`referenceImageUrl` agregados a `referenceImagesApi.ts` (+3 tests).
